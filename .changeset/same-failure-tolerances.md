A permanently broken asset no longer turns off every pass tolerance. Since capture health (schema 2.7.0), no pass criterion passed an unhealthy capture whose pixels differed, so a site whose web font or stylesheet fails on every CI run lost `maxDiffPercent`, `maxDiffPixels` and `shiftTolerance` on every affected snapshot, and a small anti-aliasing diff failed even with the baseline unhealthy in the same way. Now, when both sides are unhealthy with exactly the same failures (the same font faces by family, weight and style, the same failed stylesheets, and the same failed stylesheet and font requests by host, path and status), results.json schema 2.8.0 (additive) sets `snapshots[].captureHealth.sameOnBothSides: true` and those three tolerances apply again (`autoPassed` `"threshold"` or `"shift"`). `noiseAutoPass` never passes an unhealthy capture, `dom.noiseHint` stays false, and the reading is still **Unhealthy capture**, never render noise: the HTML report, the `@testivai/mcp` verdicts, `explain_snapshot` guidance and triage rubric, and the GitHub Action comment add "the baseline was captured with the same failures", that the tolerances still apply but noise auto-pass does not, and which criterion passed it. It is never "the same" while web fonts were still loading on either side, when one side could see what the other could not (Font Loading API, request statuses), or when a list may have been cut at 10 entries; broken images and failed scripts are not compared (they are warnings). One side unhealthy, or different failures, behave as before. `@testivai/witness/report` exports `sameHealthFailures`, `healthAllowsTolerances` and `SAME_FAILURES_NEXT`; `parseReportData` keeps `sameOnBothSides` only as `true` with `unhealthy: "both"`.
