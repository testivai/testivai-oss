Capture provenance: every capture now records where it came from, and the report says when a diff is the machine changing rather than the page. The Playwright, WebdriverIO and Selenium (JS) adapters and `testivai witness <url>` write an `environment` block into the capture's `metadata.json`: the OS (and the Linux distro), the browser and its version (and the WebDriver binary), the test framework, the adapter and how it took the screenshot (`full-page:cdp`, `full-page:playwright`, `full-page:stitched`, `viewport:webdriver`), what the page was rendered with (viewport, device scale, color scheme, reduced motion, locale, time zone, measured in the page), the CI provider and runner image, a container, and `TESTIVAI_ENV_LABEL`. Approving a capture freezes its block into the baseline's `metadata.json` (and drops a stale one). The compare reads both blocks: results.json schema 2.5.0 (additive) adds `snapshots[].environment` (`delta`, `renderingDelta`, both blocks when they differ) and a run-level `environment` (the fields every capture of the run agrees on). Framework, adapter and driver versions, the CI runner image, the project and the Linux kernel are context; the rest can change rendering. A diff whose DOM is identical, whose computed styles match and whose rendering environment changed is now **rendering drift** in the HTML report, `@testivai/mcp` (`get_visual_results` verdicts, its grouping and a new opening line when several snapshots share one change; `explain_snapshot`'s new `layers.environment`; the `triage-visual-diff` rubric) and the GitHub Action comment, never "likely render noise"; a size change from another capture method says so instead of "page grew". New config `environmentPolicy`: `"warn"` (default) never changes a status; `"separate"` keys snapshots `<name>__<browser>__<platform>` (never by version) and reports missing only the baselines of an environment the run captured; `"strict"` makes a rendering change of environment `changed` whatever its pixels say. New `testivai env` prints this machine's part of the block (`--fonts` adds a fingerprint of the installed fonts, `--json` for machines). `@testivai/witness` exports the collectors (`collectHostEnvironment`, `RENDER_PROBE_EXPRESSION`, `browserFromCapabilities`, `webDriverEnvironment`, `applyEnvironmentPolicyToName`, …) and `@testivai/witness/report` the readings (`diffEnvironments`, `isRenderingDrift`, `environmentChangeGroups`, `environmentChangeLine`, …). `BaselineStore` gains `writeTempMetadata` and `readTempMetadata`. The WebdriverIO and Selenium `WitnessBrowser` / `WitnessDriver` types gain the optional `capabilities` / `getCapabilities()` they read the browser from. The Python, Ruby and Java adapters do not record the block yet; their captures compare exactly as before.
