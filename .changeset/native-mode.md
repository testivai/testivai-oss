Native app screens (experimental): `@testivai/witness-webdriverio` captures native Android and iOS app screens in an Appium session. In a session on Android or iOS that names no browser and is in the `NATIVE_APP` context (or, when the context cannot be read, was started with `app`, `appPackage` or `bundleId`), `witness()` runs no page script: a native screen has no page, Appium rejects them there and WebdriverIO resends each failed one three times (~1.5 s each, ~8 s per capture on an Android 14 emulator). The capture is the whole screen, pixel diff only. The status bar is masked per capture (`masks: [{ "top": <px> }]` in the capture's `metadata.json`, from `mobile: viewportRect` at capture time, else the session capabilities). The environment block comes from the capabilities, with `browser.name: "native-app"`, capture method `screen:appium` and a new `device` section (platform, OS version, model, the requested device name, the Appium driver, screen size, density). The snapshot is keyed `<name>__<platform>-<device>-<osMajor>` (`login__android-pixel_7-15`) unless the call gives a `variant`. New options `native` (`true` forces native mode, `false` keeps the web path) and `maskStatusBar` (default `true`); `WitnessBrowser` gains the optional `getContext()`. A hybrid app in a web view, and every browser session, keep the web path, and a browser session makes no extra call. Verified on an Android 14 emulator in CI; iOS is not verified.

`@testivai/witness`: results.json schema 2.9.0 (additive) adds the `device` section of a snapshot's environment blocks and capture method `screen:appium`. The device's platform, OS version, model, screen and density can change rendering; the device name and the Appium driver are context, and so is `os` (the machine running the tests) when both sides are native app captures. The report words device changes ("device sdk_gphone64_x86_64 → Pixel 7, device OS 14 → 15") and the capture method ("full screen (Appium)"). New exports: `appiumEnvironment`, `isNativeAppCapabilities`, `mobilePlatform`, `namesBrowser`, `nativeAppDevice`, `nativeAppVariant`, `statusBarFromCapabilities`, `statusBarFromViewportRect`, `CAPTURE_METHODS.APPIUM_SCREEN` and the `DeviceEnvironment` type. Guide: docs/guides/native-mobile.md.
