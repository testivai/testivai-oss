Capture health: an unhealthy capture is never "render noise". A web font that failed and fell back to a system font, or a stylesheet that answered 404, leaves the DOM identical and the computed styles matching (the style digest hashes the declared `font-family`, not the font that rendered), so its small, scattered diff read "likely render noise" and `noiseAutoPass` passed it. The Playwright JS/TS adapter and `testivai witness <url>` now record, after each screenshot, what failed to load as `health` in the capture's `metadata.json`: `document.fonts.status` and every font face that errored, `<link rel=stylesheet>` elements that did not load, broken `<img>`s, and requests that answered 400 or more (Resource Timing, Chromium 109+), each URL as host and path only, never the query string. The crawler also merges the failed requests it saw on the network (CDP), cross-origin ones included. Approving freezes the capture's health into the baseline's `metadata.json`. results.json schema 2.7.0 (additive) adds `snapshots[].captureHealth` (both blocks, `unhealthy`: `"candidate"` / `"baseline"` / `"both"` / `null`, and `reasons` and `warnings` in plain words), present when either side recorded health, new snapshots included. Web fonts still loading, a font face that failed, a failed stylesheet, or a failed stylesheet request make a capture unhealthy (a failed font request only with a font face that failed, since a face can load from its next `src`; a `fetch()`/XHR request or a `<link>` that no `<link rel=stylesheet>` names and that does not end in `.css` is never a stylesheet): `dom.noiseHint` is then false and no pass criterion (`noiseAutoPass`, `maxDiffPercent` / `maxDiffPixels`, `shiftTolerance`) applies while pixels differ; a zero-pixel diff still passes. The HTML report, `@testivai/mcp` (`get_visual_results` verdicts, `explain_snapshot`'s new `layers.health` and guidance, the `triage-visual-diff` rubric and the review prompt; unhealthy captures are never grouped) and the GitHub Action comment read **Unhealthy capture** with what failed, before any other reading (rendering drift too, when both are true), and call out an unhealthy baseline on every compare against it ("re-baseline from a healthy run"). Broken images, failed scripts and other requests are warnings only. `testivai approve` warns when the capture it promotes is unhealthy. `@testivai/witness` exports `HEALTH_PROBE_EXPRESSION`, `parseHealth`, `mergeResourceFailures` and the types, and `@testivai/witness/report` the readings (`assessHealth`, `snapshotCaptureHealth`, `captureHealthReading`, `isUnhealthyCapture`, `approveHealthWarning`). The WebdriverIO, Selenium, Python, Ruby and Java adapters do not record health yet: their captures read "not checked" and compare exactly as before.
