Four fixes found running React Native screens through react-native-web.

- **A claimed shift is checked against the pixels.** Element maps pair elements by path, and content inserted above an element renumbers its `:nth-of-type` path, which can pair it with a look-alike neighbour (same size and styles, different content). That read as a shift by a wrong distance (−16 px while the content moved +64 px) with a wrong `pageShift`. A pair now counts as a shift, in `regions` and in `pageShift`, only when the element's pixels match at its new position: at most 1% differ, at the diff's colour threshold, masks excluded, best of ±1 px. In real Chrome true shifts differed on 0.00% of their pixels (fractional moves included), look-alike neighbours on 4.8–6.7%. Shifts that were right before are unchanged; wrong ones now read as `change`, which also keeps `shiftTolerance` from passing them.
- **`<script>` attribute values are not a DOM change.** A script never renders, but a bundle renamed by content hash (Expo's `index-<hash>.js`), its `integrity` and a per-request `nonce` counted as attribute changes, so a stylesheet-only change did not read style-only. Their presence still counts, and so does a script added or removed. A snapshot whose only DOM difference was a script attribute now has `dom.changed: false`, so its noise hint follows the style check.
- **The Playwright adapter restores the device emulation its full-page capture drops.** The default capture's beyond-viewport screenshot, over the adapter's own CDP session, left the page without its emulation for the rest of the test (Pixel 7: `devicePixelRatio` 2.625 → 1, touch off). `witness()` now puts back the pixel ratio and touch emulation after everything it measures, and `metadata.json` records the pixel ratio the image was rendered at: 1 for a Chromium CDP capture, which used to record the profile's value. A baseline approved before this, on a Chromium profile with a `deviceScaleFactor` other than 1, reads as an environment change in `render.deviceScaleFactor` until it is re-approved: wording only by default, a status change with `environmentPolicy: "strict"`. The captured images do not change.
- **No "Browser screenshot failed" on WebKit and Firefox.** They are captured with Playwright's full-page screenshot directly; a CDP failure on Chromium is still reported.
